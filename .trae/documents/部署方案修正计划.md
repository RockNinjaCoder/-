# 部署方案修正计划

## 问题说明

用户指出部署文档中前端使用了 nginx，认为这与后端 FastAPI 冲突。实际上当前设计是：

**正确的架构：**
```
用户浏览器 -> nginx (80端口, 前端静态服务器) -> /api/* -> FastAPI (8000端口)
```

nginx 在此作为：
1. **静态文件服务器**：托管 React 构建产物
2. **反向代理**：将 /api/ 请求转发到 FastAPI

**不是**把 FastAPI 改成了 nginx，而是两种服务配合使用。

---

## 修正方案

如果用户认为不需要 nginx 作为前端服务器，可以选择以下方案之一：

### 方案 A：保持 nginx（推荐生产环境）

- nginx 托管前端静态文件
- nginx 反向代理 API 请求到 FastAPI
- FastAPI 处理所有 /api/* 请求

### 方案 B：纯 FastAPI 部署（开发环境）

- 不使用 nginx
- 前端开发服务器 (npm run dev) 直接访问 FastAPI
- FastAPI 可以配置静态文件服务

### 方案 C：分离部署

- FastAPI 部署在 8000 端口
- 前端单独部署（静态服务器或 CDN）

---

## 建议

保留 nginx 配置，因为：
1. 生产环境需要静态文件服务器
2. nginx 可以处理缓存、压缩、反向代理
3. FastAPI 本身不擅长托管大量静态文件

如需修改部署文档，请确认选择哪个方案？
