# 前端功能问题修复计划

## 问题分析

从代码分析中发现以下问题：

### 1. ChatArea.jsx 第 90 行数组索引错误

**问题位置**: `frontend/src/components/ChatArea.jsx` 第 90 行

```javascript
const lastMsg = messages[messages.length]  // 错误！数组越界
```

`messages.length` 返回数组长度（例如 5），但数组索引从 0 开始，所以最大索引是 4。正确写法应该是：

```javascript
const lastMsg = messages[messages.length - 1]  // 正确
```

### 2. NL2SQL 查询失败

API 测试中查询"每个用户有多少订单？"失败，返回的是自然语言描述而非 SQL。

**原因**: MiniMax 模型在某些复杂查询时生成的文本包含了 "CREATE" 关键字被错误拦截。

### 3. 可能的 API 调用问题

前端发送消息到 `/api/chat` 时，可能存在参数不匹配问题。

---

## 修复步骤

### Step 1: 修复 ChatArea.jsx 数组索引 bug
- 将 `messages[messages.length]` 改为 `messages[messages.length - 1]`

### Step 2: 改进 NL2SQL 提示词
- 修改 `sql_generator.py` 的提示词，减少复杂 SQL 生成
- 过滤掉生成内容中的非 SQL 关键字（如自然语言描述）

### Step 3: 验证修复
- 重启后端服务
- 测试发送消息功能
- 测试 NL2SQL 查询功能

---

2. 流式输出能正确追加到消息中
